# Sendina — Монетизатор

Рабочая основа продукта по предоставленному ТЗ: русско-английский интерфейс, кампании, адресаты, предпросмотр писем, учёт ответов, домены, журнал, защитные правила и MCP для управления из ChatGPT.

**Это версия 0.1, а не завершённая автономная система 100/100.** Данные на стартовой панели — явно обозначенные примеры. Реальная отправка отключена. Внешнее исследование, автоматический поиск контактов и обработка входящей почты пока не подключены.

## Сайт

https://annetbg-wq.github.io/sendina/

GitHub Pages обслуживает интерфейс, API развёрнут на Railway: https://sendina-production.up.railway.app

Рабочая область защищена токеном: на первом экране нужно ввести `APP_TOKEN` сервера. Токен хранится только в sessionStorage вкладки. Кнопка «Посмотреть демонстрацию» переводит браузер в демонстрационный режим без сервера — данные сохраняются в localStorage только текущего устройства. Вернуться к серверу можно на экране «Настройки». API и MCP нельзя запустить на GitHub Pages.

## Локальный запуск

Требуется Node.js 24.

```sh
npm ci
npm run dev
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:3001.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:gate
```

На Windows можно использовать установленный Edge: `$env:PLAYWRIGHT_CHANNEL='msedge'` перед браузерными тестами. Тесты API используют отдельный временный каталог; браузерные тесты — `data/e2e` и отдельные порты.

## Данные и доступ

- Без `DATABASE_URL` сервер хранит состояние атомарно в `data/state.json`; это режим одного процесса.
- При `DATABASE_URL` используется PostgreSQL: состояние рабочей области хранится в JSONB с транзакционной блокировкой. Нормализованная схема и многопользовательская изоляция относятся к следующему этапу.
- По умолчанию API слушает loopback. Публичный адрес включается только вместе с `APP_TOKEN`: без токена сервер не стартует. Для внешнего доступа задайте `ALLOWED_ORIGINS=https://annetbg-wq.github.io`; см. «Сервер на Railway».
- Пользовательский токен UI хранится только в sessionStorage. OAuth-токены MCP не сохраняются в данных.
- Не добавляйте `.env`, токены, реальные адресаты и содержимое `data/` в репозиторий.

## Единое ядро операций

`server/operations.ts` — единственный слой действий. Интерфейс вызывает его через тонкие маршруты Express, MCP вызывает те же функции напрямую в процессе, без обращения к localhost. Одна проверка схемы, одно решение по правилам, одна запись в журнал — независимо от того, пришло действие из браузера или из ChatGPT.

| Действие | Интерфейс | MCP |
|---|---|---|
| Кампании | Рассылки | `create_campaign`, `list_campaigns`, `get_campaign`, `set_campaign_status` |
| Адресаты | «Найти адресатов», «Импорт JSON» | `find_recipients`, `import_contacts`, `confirm_recipient` |
| Письма | «Подготовить письма» | `prepare_messages` |
| Ответы | Экран «Ответы» | `record_reply`, `exclude_recipient` |
| Метрики | Главная и Аналитика | `get_dashboard`, `get_capabilities` |
| Ящики | Домены и почты | `list_mailboxes`, `test_mailbox` |
| Остановка | Настройки | `emergency_stop` |

## Поиск адресатов

Два режима, переключатель на экране «Настройки»; по умолчанию выбирается автоматически.

- **Поиск в интернете** — при заданных `SEARCH_PROVIDER` и `SEARCH_API_KEY` (`brave`, `tavily` или `serper`). Модель составляет профиль клиента и запросы, поиск возвращает настоящие ссылки, модель отбирает кандидатов.
- **Предложения модели** — когда поискового ключа нет. Модель предлагает организации и роли, но адреса и ссылки всегда пустые.

Модель не может выдумать адрес или источник, и это проверяется механически, а не обещанием в подсказке:

- `sourceUrl` кандидата должен буквально совпадать с одной из ссылок, вернувшихся из поиска, иначе кандидат отбрасывается;
- адрес сохраняется, только если он дословно встречается в тексте этого результата, иначе поле очищается, а адресат получает статус «не подтверждён»;
- неподтверждённый адресат блокируется правилом `SOURCE_UNVERIFIED` и не может попасть в отправку, пока его не подтвердят через «Подтвердить адресата» или `confirm_recipient` — с настоящим адресом, ссылкой и доказательством.

Повторный поиск не создаёт дублей. Ручной импорт JSON остаётся дополнительным режимом с теми же требованиями к источнику, основанию и причине контакта.

## Подготовка писем

«Подготовить письма» строит черновики и решение по правилам для каждого адресата: причина контакта, источник, статус подтверждения и код решения. Повторный вызов не создаёт дубликаты.

Адресат без конкретной причины контакта получает не персональное, а общее письмо, помечается как похожее на спам и блокируется правилом `CONTACT_REASON_REQUIRED`. Это разные тексты, а не одна и та же рассылка с подстановкой имени.

При переводе кампании в активное состояние выполняется автопроверка повторов: адреса, уже занятые другой кампанией, попадают в отчёт и блокируются правилом `DUPLICATE_RECIPIENT`.

## Подключение почтовых ящиков

Рабочий сценарий — корпоративный ящик на домене организации. Личный Gmail поддерживается, но помечается как вторичный тестовый случай.

Порядок: **адрес → определение провайдера по MX → OAuth или SMTP → тестовая отправка → статус «готов»**.

1. «Подключить ящик», ввод адреса. Провайдер определяется по MX-записям домена: Google Workspace, Microsoft 365 или, если MX не распознан, SMTP. Определение — это только чтение DNS, оно ничего не подключает.
2. Google Workspace и Microsoft 365 подключаются через OAuth: согласие открывается во вкладке провайдера, refresh token сохраняется на сервере. Остальные ящики — по SMTP с проверкой соединения при подключении.
3. Если домен закрыт почтовым шлюзом (Proofpoint, Mimecast и подобные), MX укажет на шлюз, а не на настоящего отправителя. В этом случае провайдера можно выбрать вручную.
4. «Тестовая отправка» отправляет одно настоящее письмо на сам ящик через подключённый аккаунт. Результат сохраняется вместе с причиной ошибки.

Статус `ready` появляется только когда выполнено всё сразу: ящик подключён, тестовая отправка прошла успешно, DNS домена проверен и содержит SPF, DKIM и DMARC. Невыполненные условия показываются списком, а не по одному.

**Проверка DNS подключением не считается.** Идеальные SPF, DKIM и DMARC при неподключённом ящике дают `NOT_CONNECTED`, и домен остаётся не готов. Домен готов, когда готов хотя бы один его ящик; готовность домена включает `verified` в решении по правилам для кампаний.

Секреты — refresh token провайдера и пароль SMTP — хранятся в `auth_store` рядом с ключами OAuth и никогда не попадают в `/api/state` и в интерфейс.

| Переменная | Назначение |
|---|---|
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | OAuth для Google Workspace и Gmail |
| `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` | OAuth для Microsoft 365 |
| `MICROSOFT_TENANT` | необязательно, по умолчанию `common` |

Redirect URI для обоих провайдеров: `https://sendina-production.up.railway.app/oauth/mailbox/callback`. Без client id и secret интерфейс честно сообщает, что OAuth не настроен, и предлагает SMTP.

## MCP / ChatGPT

Endpoint: `https://sendina-production.up.railway.app/mcp`, транспорт Streamable HTTP.

Встроенный сервер авторизации OAuth 2.1 включается сам, когда задан `APP_TOKEN`, а `OAUTH_ISSUER` пуст. Внешний провайдер не нужен.

| Endpoint | Назначение |
|---|---|
| `/.well-known/oauth-protected-resource/mcp` | Метаданные защищённого ресурса |
| `/.well-known/oauth-authorization-server` | Метаданные сервера авторизации |
| `/oauth/register` | Динамическая регистрация клиента (RFC 7591) |
| `/oauth/authorize` | Согласие оператора, PKCE S256 обязателен |
| `/oauth/token` | Обмен кода и обновление токена |
| `/oauth/jwks` | Публичный ключ подписи |

Подключение в ChatGPT: добавьте коннектор с адресом `https://sendina-production.up.railway.app/mcp`. ChatGPT сам зарегистрирует клиента и откроет экран согласия — на нём нужно ввести `APP_TOKEN` рабочей области. Экран согласия следует языку браузера.

Ключ подписи и зарегистрированные клиенты хранятся отдельно от рабочей области (`auth_store` в PostgreSQL либо `data/auth.json`) и не попадают в `/api/state`. Токены не передаются в инструменты и не сохраняются в данных.

Права: `sendina:read` для чтения, `sendina:write` для изменений. Инструменты имеют read/write-аннотации. `MCP_TOKEN` остаётся только для локального клиента без OAuth.

## Реализованные сценарии

- Создание кампании с контекстом, рынком и обязательным целевым событием.
- Импорт JSON-адресатов: email, имя, компания, источник, основание, конкретная причина контакта. Повторный импорт не создаёт дубль в кампании.
- Предпросмотр первых пяти писем; повторный запрос не создаёт дубликаты черновиков. Текст составляется из введённых фактов, без заявления о работе ИИ.
- Ручная регистрация ответа через API; повтор `eventId` не дублирует событие. Отписка и отказ создают глобальное исключение.
- Проверки остановки, состояния кампании, исключения, наличия ответа, основания контакта, домена и общего лимита. Все предпросмотры получают версию решения и причину блокировки.
- Реальная проверка наличия SPF, DKIM и DMARC через серверный DNS. Наличие записей не делает домен автоматически готовым к отправке.
- Подключение ящиков: определение провайдера по MX, OAuth для Google Workspace и Microsoft 365, SMTP как запасной вариант, ручной выбор провайдера при почтовом шлюзе.
- Тестовая отправка настоящего письма и явный статус готовности домена и ящика со списком невыполненных условий.
- Единый серверный слой операций: интерфейс и MCP выполняют одни и те же функции, MCP больше не ходит на localhost.
- Поиск адресатов в двух режимах с механической проверкой источника и адреса; неподтверждённые кандидаты не проходят правила.
- Подготовка писем с причиной контакта и решением по правилам; письмо без причины помечается как спам отдельным текстом.
- Автопроверка повторяющихся адресов при переводе кампании в активное состояние.
- Встроенный сервер авторизации OAuth 2.1 с PKCE и динамической регистрацией клиента для коннектора ChatGPT.
- Аварийная остановка. Её снятие не возобновляет кампании автоматически.
- RU/EN для экранов, форм и уведомлений; язык сохраняется, пользовательские тексты не переводятся.
- Вход по токену для защищённой рабочей области, переключение языка прямо на экране входа и переход в демонстрацию без сервера.

## Что ещё требуется по полному ТЗ

SMTP/API-адаптер и очередь с защитой от повторной отправки; автоматическое получение ответов; версионированные правила юрисдикций; динамические лимиты по репутации; оркестрация экспериментов и перераспределение объёма; подтверждённые доставки и ценность результата; полноценные workspace/RBAC и нормализованная схема БД вместо JSONB.

Сейчас `/api/send` всегда возвращает 409. Это явная граница реализации, а не имитация доставки.

## Сервер на Railway

GitHub Pages отдаёт только интерфейс. Проверка DNS, MCP и общая рабочая область требуют Node-сервера.

1. Railway → **New Project** → **Deploy from GitHub repo** → `annetbg-wq/sendina`. Файл `railway.json` задаёт сборку, запуск и проверку `/api/health`.
2. Добавьте в проект **PostgreSQL**. Railway сам подставит `DATABASE_URL`. Без него состояние лежит в файловой системе контейнера и пропадает при каждом развёртывании.
3. Переменные сервиса:

   | Переменная | Значение |
   |---|---|
   | `APP_TOKEN` | случайная строка; без неё сервер не слушает публичный адрес и не включает OAuth |
   | `ALLOWED_ORIGINS` | `https://annetbg-wq.github.io` |
   | `PUBLIC_URL` | `https://sendina-production.up.railway.app` |
   | `DATABASE_URL` | подставляет Railway вместе с плагином PostgreSQL |
   | `OPENAI_API_KEY` | ключ OpenAI; без него поиск адресатов и подготовка писем откажутся работать |
   | `OPENAI_MODEL` | необязательно, по умолчанию `gpt-4.1-mini` |
   | `SEARCH_PROVIDER` | необязательно: `brave`, `tavily` или `serper` |
   | `SEARCH_API_KEY` | ключ выбранного поиска; без него кандидаты остаются неподтверждёнными |
   | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | необязательно: OAuth для Google Workspace |
   | `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` | необязательно: OAuth для Microsoft 365 |

   `PORT` и `HOST` задавать не нужно: `PORT` приходит от Railway, а публичный адрес включается по `RAILWAY_ENVIRONMENT_NAME`.
4. **Settings → Networking → Generate Domain**. Получится адрес вида `https://sendina-production.up.railway.app`.
5. В GitHub: **Settings → Secrets and variables → Actions → Variables** → `VITE_API_URL` = адрес из шага 4 (уже задан). Переменная читается при сборке, поэтому после её изменения нужен новый запуск workflow «Deploy GitHub Pages». Это переменная сборки, она попадает в браузер — секреты в неё класть нельзя.
6. Откройте сайт, на экране «Настройки» введите `APP_TOKEN`. Токен хранится только в sessionStorage вкладки.

Без `VITE_API_URL` сайт остаётся демонстрацией в браузере: данные не покидают устройство, проверка DNS и MCP недоступны. Сохранённый в браузере адрес сервера имеет приоритет над `VITE_API_URL`; пустое значение выбирает демонстрационный режим.

## Публикация

Workflow `.github/workflows/pages.yml` проверяет тесты, собирает приложение с `/sendina/` в качестве base path и публикует `dist` через GitHub Pages. Необязательная repository variable `VITE_API_URL` задаёт адрес отдельного API. Секреты нельзя помещать в переменные `VITE_*`: они попадают в браузер.

[GitHub Pages deployment documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
